# 프로토타입 구현 계획

> 작성 2026-08-31 · 대상: [GAME_DESIGN.md](GAME_DESIGN.md)의 프로토타입 범위

## 이 문서의 목적

프로토타입을 순서대로 쪼개고, 각 작업에 **메이커가 필요한지**와 **어떤 문서를 먼저 읽어야 하는지**를 적어둔다. 세션이 바뀌어도 같은 자리에서 이어갈 수 있게 하는 것이 목적이다.

## 확인하려는 질문

> **헤네시스를 먼저 깨고 그 능력으로 페리온을 깨는 것이 재미있는가.**

이 질문에 답하는 데 필요 없는 것은 만들지 않는다. 로그라이크 층(죽음, 구슬, 해금)은 이 질문에 답한 뒤에 붙인다.

## 현재 있는 것

| 자산 | 위치 | 상태 |
|---|---|---|
| 포자 발판 스크립트 | `RootDesk/MyDesk/JumpPad/JumpPadComponent.mlua` | 동작 확인됨 |
| 포자 발판 모델 | `RootDesk/MyDesk/Models/MapObjects/JumpPad.model` | 4개 컴포넌트 |
| 테스트 맵 | `map/TileMapTemplate.map` | MapleTile 사이드뷰, JumpPad01 배치됨 |

포자 발판은 맵에 **고정 배치된 오브젝트**다. 기획상으로는 보스를 잡아야 얻는 **능력**이므로, 플레이어가 원할 때 설치하는 형태로 바꿔야 한다. 이것이 T2다.

## 작업 순서

### 1단계 — 상성 한 쌍 검증 (핵심)

| # | 작업 | 메이커 | 먼저 읽을 것 |
|:-:|---|:-:|---|
| T1 | 헤네시스 맵 만들기 (기존 템플릿 복제해 시작) | 필요 | `msw-general` Map Work Preflight |
| T2 | 포자 발판을 설치형 능력으로 전환 | 일부 | `msw-scripting`, 기존 JumpPadComponent |
| T3 | 페리온 맵 만들기 | 필요 | T1과 동일 |
| T4 | 페리온 보스 — 체력, 패턴 1개, 피격 판정 | 필요 | `msw-combat-system`, `knockback-hit-reaction.md` |
| T5 | 페리온 보스에 포자 발판 약점 판정 붙이기 | 일부 | T4 결과 |

**T5까지 하면 질문에 답할 수 있다.** 여기서 재미없으면 방향을 다시 잡는다.

### 2단계 — 로그라이크 층

1단계가 재미있다고 확인된 뒤에만 시작한다.

| # | 작업 | 메이커 | 먼저 읽을 것 |
|:-:|---|:-:|---|
| T6 | 판 상태 관리 — 보유 능력, 죽으면 초기화 | 일부 | `architecture/framework.md` |
| T7 | 마력 구슬 — 획득과 판 넘어 저장 | 필요 | `architecture/datasets.md` |
| T8 | 구슬 사용처 1개 — 시작 체력 | 필요 | T7 결과 |

### 3단계 — 나머지 지역

2단계까지 검증되면 엘리니아 · 커닝시티 · 리스항구는 복제 작업이다. 상성 순환을 닫고 슬리피우드를 붙인다.

## 작업 규칙

### 스킬 데이터는 하드코딩하지 않는다

`datasets.md`에 명시되어 있다. 스킬은 `UserDataSet` 행으로 작성하며, 스크립트에 박아넣은 스킬 테이블은 요건을 만족하지 않는다. 데이터셋은 메이커에서 만들어야 하는 자산이므로 **메이커 없이 스킬 코드를 먼저 쓰지 않는다.**

### 모델과 맵은 손으로 편집하지 않는다

`msw-general`의 Model Work Preflight와 Map Work Preflight에 따라 빌더를 통한다. `.model`과 `.map`을 직접 고치면 타입이 어긋나 런타임에 컴포넌트 생성이 실패한다. 실제로 겪었다 — 아래 지뢰 목록 참고.

### 재생 검증은 사람이 한다

AI에게 재생까지 맡기지 않는다. "고친 뒤에 알려줘, 재생 확인은 내가 한다"로 범위를 자른다. 이유는 아래.

## 오늘 밟은 지뢰 (2026-08-31)

같은 곳을 다시 밟지 않기 위한 기록.

### 1. 재생 모드에 갇힘

AI가 검증하려고 재생을 켜면 스스로 끄지 못하는 상태에 빠진다. 재생 중에는 `Workspace refresh is disabled during Play Test`로 파일 갱신이 막혀 그때부터 아무것도 진행되지 않는다. 정지 시도 6회, 12분을 날렸다.

**Scene 탭으로 돌아가는 것만으로는 재생이 멈추지 않는다.** 보는 화면만 바뀌고 세션은 계속 돌아간다. 메이커를 껐다 켜는 것이 가장 빠른 해결이며, 다시 켤 때 파일을 새로 읽으므로 갱신도 같이 된다.

**예방:** 재생 검증을 AI에게 맡기지 않는다.

### 2. ColliderType 타입 오류

`.model`을 직접 만들면서 `ColliderType`이 열거형 대신 `System.Int32` / `Value: 0`으로 저장됐다. 0은 Undefined라 `unhandled component case : TriggerComponent` 예외가 나고 컴포넌트가 아예 생성되지 않는다.

**해결:** 해당 속성 블록을 지우면 기본값 Box를 쓴다.
**예방:** 모델은 빌더를 통해 만든다.

### 3. 로그는 찍히는데 동작하지 않음

발판을 밟으면 로그가 14번 찍혔는데 캐릭터는 움직이지 않았다. `MoveVelocity`에 값을 넣었기 때문인데, 이건 걷기 속도라서 이동 로직이 매 프레임 덮어쓴다.

MapleTile에서 위로 튕기려면:

```lua
rb.MoveVelocity = Vector2.zero          -- 먼저 지운다
rb:JustJump(Vector2(0, force))          -- 수직 점프
```

`msw-combat-system/SKILL.md`에 `AddForce` · `SetForce` · `JustJump` 용법이 정리되어 있다.

**교훈:** 로그는 코드가 실행됐다는 것만 알려주지 의도한 결과가 나왔는지는 알려주지 않는다. 화면을 직접 봐야 한다.
