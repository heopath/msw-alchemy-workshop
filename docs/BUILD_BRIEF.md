## 0. 작업 규칙 (반드시 지킬 것)

### 재생 금지

**절대 `maker_play`를 호출하지 않는다.** 재생 검증은 사람이 한다.

이유는 [IMPLEMENTATION_PLAN.md](IMPLEMENTATION_PLAN.md)의 지뢰 목록 1번 참고. 재생을 켜면 스스로 끄지 못해 작업 전체가 멈춘다.

### 확인 항목은 목록으로 쌓는다

**2026-08-31 변경.** 태스크마다 멈추지 않고 T3부터 T7까지 이어서 진행한다. 사람은 마지막에 한 번에 확인한다.

대신 태스크가 끝날 때마다 **[VERIFY_CHECKLIST.md](VERIFY_CHECKLIST.md)에 확인 항목을 누적**한다. 이것이 사람이 검증할 때 쓰는 유일한 문서이므로, 여기에 안 적으면 확인되지 않은 채 넘어간다.

한 항목은 이 형식으로 적는다.

```
- [ ] **T3 — 능력 획득 전 설치 차단**
  어디서: MapHenesys
  조작: 보스를 잡기 전에 설치 키를 누른다
  기대: 아무것도 설치되지 않는다
  실패하면: _AbilityLogic의 보유 판정
```

`실패하면` 칸에는 그 항목이 어긋났을 때 **어느 파일이나 로직을 봐야 하는지**를 적는다. 나중에 고칠 때 원인을 다시 찾는 시간을 줄이기 위한 것이다.

태스크 사이에는 한 줄만 보고하고 바로 다음으로 넘어간다.

```
T3 완료 (확인 항목 4개 추가). T4 시작.
```

### 이어서 진행하되 멈춰야 할 때

아래 경우에는 다음 태스크로 넘어가지 말고 사람에게 묻는다.

- 지시서의 수치나 설계로는 만들 수 없는 구조적 문제를 발견했을 때
- 앞 태스크의 결과물을 고쳐야 다음 태스크가 가능할 때
- 같은 자리에서 10분 넘게 막혔을 때

### 모델과 맵은 빌더로

`.model`과 `.map`을 텍스트로 직접 편집하지 않는다. 타입이 어긋나 런타임에 컴포넌트 생성이 실패한다. 지뢰 목록 2번 참고.

### 재생 중에는 `.map`과 `.model`을 아예 쓰지 않는다

**2026-08-31 추가.** 재생 중에 맵이나 모델을 쓰면 **파일에는 써지지만 다음 갱신 때 조용히 사라진다.** 메이커가 그 파일을 메모리에 들고 있다가 자기 사본을 디스크로 다시 쓰기 때문이다.

실제로 잡몹 12마리 배치와 보스 체력 상향이 통째로 되돌아갔다. 오류도 경고도 나지 않는다. 갱신 뒤에 확인해야만 알 수 있다.

재생 중이면 **작업 자체를 멈추고 사람이 끄기를 기다린다.** 재생을 대신 끄지는 않는다. `.mlua`는 메이커가 메모리에 들고 있지 않아 영향받지 않는다.

### 스킬 데이터는 하드코딩 금지

`datasets.md`의 `DATA-01`~`DATA-03`을 따른다. 스킬 테이블을 스크립트에 박아넣지 않는다.

### 검증되지 않은 것을 됐다고 말하지 않는다

재생을 못 하므로 **동작 확인은 어차피 불가능하다.** 보고할 때 "동작합니다"가 아니라 "만들었고 확인이 필요합니다"로 적는다.

로그를 심어둔 것은 동작의 증거가 아니다. 어제 발판 로그가 14번 찍히는 동안 캐릭터는 움직이지 않았다. 지뢰 목록 3번 참고.

## 2. 수치표

### 포자 발판 (헤네시스 능력)

| 항목 | 값 | 비고 |
|---|---|---|
| 튕김 세기 | 6.0 | 오늘 검증된 값 |
| 지속 시간 | 20초 | 이후 자동 소멸 |
| 동시 설치 | 2개 | 3개째 설치 시 가장 오래된 것 제거 |
| 설치 쿨다운 | 3초 | |
| 설치 위치 | 플레이어 발밑 | 지면에 있을 때만 설치 가능 |

### 헤네시스 보스 — 거대 버섯 `GiantMushroom`

| 항목 | 값 |
|---|---|
| 체력 | 600 |
| 접촉 데미지 | 10 |
| 패턴 A — 내려찍기 | 3초 주기, 예고 0.5초, 착지 시 범위 피해 15 |
| 패턴 B — 포자 발사 | 5초 주기, 전방 3발, 발당 8 |
| 페이즈 전환 | 체력 50% 이하에서 주기 3초 → 2초 |
| 처치 보상 | 포자 발판 능력 획득 |

**구현 메모 (T2).** "번갈아"와 "주기"가 함께 적혀 있어 다음으로 해석했다 —
한 사이클은 `내려찍기 → 3초 대기 → 포자 발사 → 5초 대기` 반복이고, 페이즈 전환은
내려찍기 대기만 3초 → 2초로 줄인다. 두 패턴을 모두 보려면 약 9초가 걸린다.
접촉 데미지는 플레이어의 `PlayerHit.ImmuneCooldown`(1초)에 걸려 실제로는 초당 1회 들어간다.
리소스는 `mob/3300008`(총리대신) 버섯 계열 팩을 썼다.

### 페리온 보스 — 바위 전사 `RockWarrior`

| 항목 | 값 |
|---|---|
| 체력 | 1200 |
| 접촉 데미지 | 20 |
| 패턴 — 돌진 | 2.5초 주기, 예고 0.6초, 좌우 직선 |
| 벽 충돌 경직 | 1.5초 |
| **포자 발판 충돌 경직** | **5초** ← 약점 |
| 경직 중 받는 피해 | 3배 |
| 페이즈 전환 | 체력 50% 이하에서 주기 2.5초 → 1.8초 |

**체력 상향 (2026-08-31 검증 후).** 바위 전사 300 → 1200, 거대 버섯 200 → 600.
경직 중 3배가 실제로 작동해 벽 경직 1.5초 안에 보스가 죽어버렸다(로그상 1초에 300 → 50).
발판 경직 5초를 쓸 이유가 사라져 이 프로토타입의 검증 목적 자체가 막혔다.
**3배 배율은 그대로 둔다** — 발판이 벽보다 3배 이득이라는 것이 체감돼야 하므로,
배율이 아니라 체력으로 조정한다.

**돌진은 지상에서만 판정한다.** 공중에 뜬 플레이어는 맞지 않는다. 이것이 포자 발판을 회피에도 쓸 수 있게 하는 장치다.

## 3. 약점 설계 (이 프로토타입의 핵심)

록맨식 "능력으로 보스를 공략한다"를 구현하는 부분이다. 여기가 재미없으면 기획 전체를 다시 본다.

### 의도한 플레이

1. 바위 전사가 좌우로 돌진한다
2. 플레이어가 **돌진 경로에 포자 발판을 설치한다**
3. 보스가 발판을 밟고 공중으로 튕겨 오른다
4. 착지 후 5초간 경직, 그동안 받는 피해 3배
5. 이 구간에 화력을 집중한다

### 능력 없이도 잡을 수 있어야 한다

발판이 없으면 벽 충돌 경직(1.5초)만 노려야 한다. **가능하지만 훨씬 오래 걸린다.** 록맨과 같은 구조다. 약점을 알아낸 보람이 있으려면 없을 때도 길이 있어야 한다.

### 판정 구현 방향

포자 발판의 트리거는 이미 플레이어와 몬스터를 구분하지 않고 `RigidbodyComponent`를 가진 대상을 튕긴다. 보스도 그대로 튕긴다.

보스 쪽에서 **"공중에 떴다가 착지했고, 그 원인이 포자 발판이면 5초 경직"** 을 판정한다. 발판이 튕길 때 대상에게 표식을 남기고 보스가 그것을 읽는 방식이 단순하다.

## 4. 태스크

### T1 — 헤네시스 맵

기존 `TileMapTemplate`을 복제해 `MapHenesys`를 만든다. `TileMapMode=0`(MapleTile 사이드뷰)을 유지한다.

- 좌우로 걸어다닐 수 있는 평평한 지형
- 보스전을 치를 수 있는 폭 (화면 2개 분량 정도)
- 스폰 지점 1개
- 벽으로 양끝을 막는다 (돌진 보스가 부딪힐 벽이 T4에서 필요하므로 같은 구조로 만든다)

**완료 기준.** 맵이 열리고 캐릭터가 좌우로 이동하며 양끝 벽에서 막힌다.

### T2 — 헤네시스 보스

`GiantMushroom` 모델과 체력·패턴을 만든다. 수치는 위 표를 따른다.

- 패턴 A(내려찍기), 패턴 B(포자 발사)를 번갈아
- 체력 50% 이하에서 주기 단축
- 처치 시 사망 처리와 보상 신호 발생 (보상 연결은 T3)

**완료 기준.** 보스가 두 패턴을 번갈아 쓰고, 피해를 입으면 체력이 줄고, 0이 되면 죽는다.

### T3 — 포자 발판 능력화

지금은 맵에 고정 배치된 오브젝트다. **플레이어가 설치하는 능력**으로 바꾼다.

- 기존 `JumpPad` → `SporePad`로 이름 변경
- 헤네시스 보스 처치 시 능력 획득
- 획득 후 키 입력으로 발밑에 설치
- 동시 2개, 지속 20초, 쿨다운 3초
- 능력이 없으면 설치되지 않는다

보유 능력은 `_AbilityLogic`에서 관리한다. 프로토타입에서는 능력이 하나뿐이지만, 나중에 5개가 되므로 목록 구조로 만든다.

**완료 기준.** 보스를 잡기 전에는 설치되지 않고, 잡은 뒤에는 설치되며 밟으면 튀어오른다.

### T4 — 페리온 맵

`MapPerion`을 만든다. T1과 같은 구조에 좌우 벽을 확실히 둔다. 돌진 보스가 벽에 부딪히는 것이 기본 공략이므로 벽 위치가 중요하다.

**완료 기준.** T1과 동일.

### T5 — 페리온 보스

`RockWarrior`를 만든다. 수치는 위 표를 따른다.

- 돌진 패턴, 예고 동작 0.6초 (플레이어가 반응할 시간)
- 벽에 부딪히면 1.5초 경직
- 경직 중 받는 피해 3배
- 돌진 판정은 지상에서만

**완료 기준.** 보스가 좌우로 돌진하고 벽에 부딪혀 경직되며, 경직 중 피해가 3배로 들어간다.

### T6 — 약점 상성 연결

포자 발판에 튕긴 보스가 **5초** 경직되게 한다. 3절 참고.

**완료 기준.** 돌진 경로에 발판을 설치하면 보스가 튕겨 오르고, 착지 후 5초간 경직되며 피해가 3배로 들어간다.

### T7 — 지역 선택

헤네시스와 페리온을 고르는 최소한의 화면. UI는 `msw-ui-system`을 따른다. 버튼 두 개면 충분하다.

**완료 기준.** 두 지역을 오갈 수 있고, 이미 깬 지역이 표시된다.

## 5. 여기까지 하면

사람이 직접 플레이해서 확인한다.

> 헤네시스를 먼저 깨고, 얻은 포자 발판으로 페리온 보스를 공략하는 것이 재미있는가.

재미있으면 [IMPLEMENTATION_PLAN.md](IMPLEMENTATION_PLAN.md)의 2단계(로그라이크 층)로 넘어간다. 재미없으면 수치와 약점 설계를 먼저 손본다. **지역을 늘리는 것은 이 질문에 답한 뒤다.**

## 6. 막혔을 때

- **모르는 API** — `msw-search`로 찾는다. 추측해서 쓰지 않는다.
- **재생이 필요한 확인** — 사람에게 넘긴다. 직접 켜지 않는다.
- **수치가 어색함** — 조정하고 이 문서를 고친다. 바꾼 이유를 한 줄 남긴다.
- **10분 넘게 같은 자리** — 멈추고 무엇이 막혔는지 보고한다. 오늘 12분을 그렇게 날렸다.

## 부록 — 구현하며 정한 것 (2026-08-31)

지시서에 없어서 만든 세션이 임의로 정한 값들이다. **지시서 표의 수치는 하나도 바뀌지 않았다.**

| 항목 | 정한 값 | 근거 |
|---|---|---|
| 발판 설치 키 | `F` | 기본 조작(방향키·Alt·Space)과 겹치지 않음 |
| 지역 선택 토글 | `M` | 시작 시 창이 열려 있음 |
| 돌진 속도 | InputSpeed 4.0 | 실효 5.6 유닛/초 (× WalkSpeed 1.4). 플레이어 걷기의 4배 — **재생으로 작동 확인됨** |
| 돌진 최대 시간 | 3초 | 벽을 못 만났을 때 탈출용 |
| 벽 감지 | 유예 0.35초 뒤, 0.15초에 0.02유닛 미만 이동 + 누적 0.4유닛 이상 이동했을 때만 벽으로 인정 | 가속 구간을 벽으로 오인하던 것을 막고, 이동 고장과 진짜 벽을 로그에서 구분 |
| 착지 유예 / 최대 체공 | 0.25초 / 3초 | 튕긴 직후 접지 오판 방지 |
| 보스 배치 | 두 맵 모두 x=5 (스폰 x=0) | |
| 포자 부채꼴 | 좌우 15도 | |
| 리소스 | 총리대신(버섯) / 캐슬 골렘(바위) | msw-search로 선택 |

### 방식을 달리한 것

- **`Monster.mlua`에 `DamageMultiplier` 추가.** 경직 중 3배 피해를 보스에 박지 않고 공용 컴포넌트에 뒀다. 두 컴포넌트가 각각 체력을 깎으면 실행 순서가 미정이라 경합이 난다. 기본값 1이라 기존 몬스터는 영향 없다.
- **접촉 피해와 돌진 피해를 한 히트박스로.** 지시서에 돌진 피해량이 없어서 `attackInfo`로 `contact`/`charge`만 나눴다.
- **`maplestory-skill-maker` 프레임워크를 세우지 않았다.** 그 틀은 피해·명중 판정이 있는 공격 스킬용이고, 포자 발판은 피해 없는 설치형이라 스키마가 맞지 않는다. 틀을 세우는 것 자체가 T3~T7 범위를 넘어선다. 지시서의 실제 요구인 "스킬 테이블을 스크립트에 박아넣지 않는다"는 자체 데이터셋으로 지켰다 — `Data/AbilityTable`, `Data/RegionTable`.
- **능력 보유가 플레이어별이 아니라 전역.** 1인 프로토타입 전제다. 쿨다운과 발판 목록만 플레이어별이다.
- **발판→보스 연결은 커스텀 이벤트.** `SporePadBounceEvent`를 튕긴 대상에게 보내고 보스가 받는다. 발판은 보스를 모르고 보스는 발판을 모른다.
