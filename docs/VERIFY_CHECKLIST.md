# 검증 체크리스트

> T3~T7을 만드는 동안 확인 항목을 누적하는 문서. 사람이 마지막에 이 목록 하나로 전체를 검증한다.
> 작성 규칙은 [BUILD_BRIEF.md](BUILD_BRIEF.md) 0절 참고.

## 검증하는 법

1. 메이커에서 **확인할 맵을 먼저 연다** (재생 버튼은 편집기에 열려 있는 맵을 실행한다)
2. 재생하고 각 항목의 조작을 해본다
3. 기대대로면 `[x]`, 아니면 그대로 두고 아래 **어긋난 것** 표에 적는다
4. 전부 훑은 뒤 한 번에 수정을 요청한다

재생을 끄고 나서 수정을 요청해야 한다. 켜둔 채로 시키면 파일 갱신이 막힌다.

## 헤네시스 한 바퀴 — 전체 플레이 순서

항목별로 훑기 전에, 처음부터 끝까지 **한 흐름으로** 한 번 해보는 순서입니다.
이대로 끊김 없이 이어지면 헤네시스는 일단 완성입니다.

```
 ┌ 지역 선택(M) ─ 헤네시스
 │
 ▼  평야 MapHenesys  −20.63 ~ 19.73 (40.36유닛)
 −19.5  시작
        │  달팽이 4  ──  주황버섯·슬라임 섞임  ──  슬라임 위주
 −17 ~ 13  잡몹 11마리 (3유닛 간격), 닿으면 5·8·6 피해
        │
   13 ~ 18.8  빈 구간 5유닛 — 한 박자 쉼
   18.8  포털 (닿거나 위 방향키)
        │
        ▼  보스방 MapHenesysBoss  −10.73 ~ 9.83 (20.56유닛)
   −7.5  도착 · 숲 배경 · 큰 나무 · 어두운 타일
   −9.8  되돌아가는 포털 (평야 15.5로)
    7.5  거대 버섯 — 체력 600
        │  내려찍기(3초) ↔ 포자 3발(5초) 번갈아, 체력 300 이하에서 주기 단축
        ▼
        처치 → 포자 발판 획득
        │
        ▼  발판 사용: F로 놓고 → 비켜서고 → 다시 밟기
           지면에서 6.0 / 공중에서 9.0, 한 번 튕기면 소멸
```

**한 흐름으로 볼 때 확인할 것 다섯 가지**

- [ ] 지역 선택에서 헤네시스를 고르면 평야 **왼쪽 끝**에서 시작한다
- [ ] 잡몹을 헤치고 오른쪽으로 나아가는 흐름이 된다 (**닿으면 피해가 들어온다**)
- [ ] 빈 구간을 지나 포털이 보이고, 보스방으로 들어가면 **다른 곳에 온 느낌**이 난다
- [ ] 보스가 두 패턴을 번갈아 쓰고, 잡으면 포자 발판을 얻는다
- [ ] 얻은 발판을 **놓고 → 비켜서고 → 밟으면** 튀어오른다

여기까지 되면 남은 것은 페리온이고, T6(발판으로 바위 전사 공략)이 이 프로토타입의 마지막 질문입니다.

## 오늘 확인된 것 (2026-08-31)

이 절은 원래 "먼저 볼 것 — 눈으로만 갈리는 미지수"였다. **전부 재생으로 확인돼 결과 기록으로 바꾼다.**

| 확인 항목 | 결과 | 원인이었던 것 |
|---|---|---|
| 양끝에서 막히는가 | ○ | 벽은 원래 있었고 `IsBlockVerticalLine`이 꺼져 있었다 |
| 보스가 실제로 돌진하는가 | ○ | `WalkAcceleration` 기본값 1로는 가속이 안 돼 가짜 벽 경직이 걸렸다 |
| 발판이 보스를 튕기는가 | ○ | `RockWarrior.model`에 `TriggerComponent`가 아예 없었다 |
| 잡몹에 닿으면 피해가 들어오는가 | ○ | 접촉 박스 높이가 몹 크기 기준이라 플레이어 몸통에 닿지 못했다 |
| 발판이 스프링으로 동작하는가 | ○ | 놓이는 순간 자기가 밟아 1회용으로 소비됐다 |
| 보스가 화면에 보이는가 | ○ | 화면 폭 12.8유닛 < 보스방 20.56유닛 |
| 평타와 내려찍기가 둘 다 되는가 | ○ | `LWA-4013` 경고는 오탐이었다 |

**여섯 개가 "로그는 정상인데 화면에서는 아무 일도 일어나지 않는" 유형이었다.** 매번 하나씩만 바꿔서 원인을 걸러냈고, 두 번은 가설이 틀려 되짚었다(판정 주기 → 박스 높이, 파괴 타이밍 → 자기소비).

이 목록의 교훈은 하나다 — **로그는 코드가 실행됐다는 것만 알려주지 의도한 결과가 나왔는지는 알려주지 않는다.**

### 맵 폭 확장 기록 (2026-08-31)

사용자 승인 하에 타일 배열을 프로그램으로 생성하고 foothold 좌표를 옮겼습니다. **16.96 → 40.36유닛.**

| 항목 | 이전 | 이후 |
|---|---|---|
| 타일 열 | x −19 ~ 17 (37열, 629칸) | x **−45 ~ 43** (89열, **1513칸**) |
| 바닥 foothold | −8.93 ~ 8.03 | **−20.63 ~ 19.73** |
| foothold 개수 | 34 | **34 (변동 없음)** |

방식은 최소 편집입니다. **foothold를 새로 만들거나 재연결하지 않았습니다.**

- 양 끝 수평 발판(fh 1, fh 18)의 바깥쪽 끝점 x만 늘리고 `Length`를 다시 계산
- 수직 벽 16개(fh 19~26, 27~34)는 x만 이동 — y·`Variance`·`Next`/`Previous`·`Id`·`attribute` 그대로
- 타일은 기존 열의 `type` 패턴이 (열 종류, y)마다 결정적인지 먼저 검증하고, `tileIndex`는 같은 종류 열에서 실제로 쓰인 값들 중에서만 뽑았습니다 (새 값을 지어내지 않음)

쓰기 전 자동 검증을 통과했습니다 — 체인 연결(Next↔Previous 상호 일치), `Length`와 실제 끝점 거리 일치, 수평 바닥 연속성(틈 0). 갱신 후 다시 읽어 벽 16개가 새 양끝에 그대로 있는 것도 확인했습니다.

## T10 — 발판 1회용 · 점프 결합 · 접촉 피해 수정 (2026-08-31)

### 포자 발판

> ⚠️ **조작 순서가 바뀌었습니다.** 발판은 **발밑에 깔리므로 처음에는 무장되지 않습니다.**
> 놓자마자 자기 자신을 소비해버리는 것을 막기 위한 것입니다.
>
> **놓는다 → 비켜선다 → 다시 밟는다.** 이 순서여야 튕깁니다.
> 놓고 그 자리에 계속 서 있으면 아무 일도 일어나지 않는 것이 **정상**입니다.
>
> T6(보스 돌진 경로에 깔고 비키기)은 이 흐름과 그대로 맞물립니다.

- [ ] **놓고 비켜서면 무장된다**
  조작: F로 발판을 놓고 옆으로 한 걸음 비킨다
  기대: 콘솔에 `SporePad placed: ... (armed=false)` → `SporePad ignored enter (not armed yet)` → 비킨 뒤 `SporePad armed: SporePad_N`
  실패하면: `SporePadComponent`의 `ArmDelay` / `OverlapCount`, `TriggerLeaveEvent` 구독
- [ ] **다시 밟으면 한 번 튕기고 사라진다**
  조작: 무장된 발판을 다시 밟는다
  기대: 튕겨 오르고 발판이 사라진다. 제자리 무한 점프가 되지 않는다
  콘솔: `SporePad bounce: ... force=6.0` → `SporePad JustJump returned true` → `SporePad trigger disabled, destroy in 0.15s`
  실패하면: 아래 표로 어디서 끊겼는지 갈립니다
- [ ] **안 밟으면 20초 뒤에 사라진다** (기존 동작 유지)
  조작: 설치하고 밟지 않은 채 20초 기다린다
  기대: `SporePad expired`
  실패하면: `SporePadComponent.Expire`
**튕기지 않을 때 — 로그 6종으로 어디서 끊겼는지 갈립니다**

| 마지막으로 보이는 줄 | 어디서 끊긴 것인가 | 볼 곳 |
|---|---|---|
| `placed:` 만 있고 그 뒤가 없음 | 트리거 자체가 안 옴 | `SporePad.model`의 TriggerComponent, 충돌 그룹 |
| `ignored enter (not armed yet)` 만 반복 | 무장이 안 됨 — 계속 밟고 서 있는 상태 | **비켜섰는지 확인.** 안 비켰으면 정상 동작입니다 |
| `armed:` 는 나오는데 다시 밟아도 `bounce:` 가 없음 | 무장 후 재진입 트리거가 안 옴 | `TriggerEnterEvent` 재발동, `OverlapCount` 계산 |
| `bounce:` 는 나오는데 안 뜸 | 힘은 계산됐는데 물리에 안 실림 | 바로 아래 `JustJump returned` 값을 봅니다 |
| `JustJump returned false` | JustJump가 거부되어 `SetForce`로 폴백 | MapleTile 물리, 공중 상태 |
| `trigger disabled, destroy in 0.15s` 까지 다 나오는데 안 뜸 | 파괴 지연으로도 안 되는 것 — 다른 원인 | 지연을 늘리거나 `Destroy` 자체를 빼고 재확인 |

- [ ] **점프 중에 밟으면 더 높이 뜬다**
  조작: 그냥 걸어가서 밟아보고, 다음엔 점프해서 밟아본다
  기대: 점프해서 밟은 쪽이 눈에 띄게 높이 뜬다
  콘솔: `grounded=true` → force 6.0 / `grounded=false` → force 9.0
  실패하면: `SporePadComponent.OnTriggerEnter`의 `IsOnGround` 분기
  참고: **올라가는 중과 떨어지는 중은 구분하지 않습니다.** 둘 다 공중이라 똑같이 9.0입니다
- [ ] **상한을 넘지 않는다**
  조작: 점프해서 밟는다
  기대: 9.0을 넘지 않아 맵 밖이나 벽 너머로 날아가지 않는다
  실패하면: `AbilityTable.csv`의 `maxBounceForce`
